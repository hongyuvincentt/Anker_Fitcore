# D05 metric dictionary — d05.metrics.v1

Input schema: `d05.input.v1`. Output schema: `d05.report.v1`. These versions change whenever denominator, matching, evidence or percentile meaning changes. No fuzzy matching, unit conversion, semantic inference or model calls occur. Finite numeric weight_kg values compare numerically (20=20.0); booleans are rejected. Reps must be a nonnegative integer in the input (8.0 is rejected). Other fields retain exact JSON type/value matching, so target index=true does not match index=1.

| Key | Unit | Numerator | Denominator |
| --- | --- | --- | --- |
| correct_auto_commit | completed_fact | One-to-one exact automatic COMMIT matches | Reviewed expected facts with temporal_modality=completed |
| wrong_commit | auto_commit | Automatic COMMITs with no unused exact completed-gold match, including extras/duplicates | All automatic COMMITs in gold-reviewed utterances |
| missed_fact | completed_fact | Reviewed completed facts left unmatched by automatic COMMITs | Reviewed expected completed facts |
| defer_pending | utterance | Utterances containing at least one automatic DEFER | All input utterances, including gold-unreviewed utterances |
| asr_transcription_error | adjudicated_utterance | Explicit manually adjudicated true flags | Explicit reviewed true or false flags for this layer |
| asr_numeric_error | adjudicated_utterance | Explicit manually adjudicated numeric-error true flags | Explicit reviewed true or false numeric flags |
| semantic_error | adjudicated_utterance | Explicit manually adjudicated semantic-error true flags | Explicit reviewed true or false semantic flags |
| fact_engine_error | adjudicated_utterance | Explicit manually adjudicated Fact Engine-error true flags | Explicit reviewed true or false Fact Engine flags |

Rates have `value=numerator/denominator` (fraction 0–1), explicit numerator/denominator/unit, status and unknown_count. An empty denominator is `unmeasured` and value=null; numerator=0 with a nonzero denominator is a measured zero. Gold-unreviewed/disputed utterances and their automatic COMMITs are excluded from all three fact rates; exclusions are counted separately. A fact rate with some excluded gold is `partial`. Never infer an unknown number of expected facts in excluded gold. `unknown_count` on error layers is missing/null flags and uses utterances, not facts. Layered errors may overlap; their sum is not a total error rate.

One input line is one utterance/case. A line may contain several facts and decisions. Each gold fact_id must be unique within its utterance. Reviewed gold requires every expected fact's temporal_modality to be resolved (completed, historical or planned); unknown/null modality rejects the case instead of silently shrinking its denominator. Keep unresolved cases unreviewed/disputed, where the whole utterance remains visibly excluded. Actual COMMIT duplicates are preserved, rather than deduplicated. A wrong weight/repetition/exercise/time/target or wrong fact_id is one wrong COMMIT and leaves the relevant gold fact missed. A correct COMMIT plus an identical duplicate is one correct match and one wrong extra. Manual confirmations are counted separately and never rescue automatic omissions. REJECT does not create a COMMIT or Pending; DEFER counts once per utterance. A reviewed planned/historical fact is not an expected completed fact; automatically committing it is wrong.

Latency is end-to-end observed latency supplied by the operator, in milliseconds, for this utterance. Each observation requires a trace/evidence reference; no latency is inferred from audio length. P50/P95 use **nearest rank**: sort n finite nonnegative observations; select index ceil(p*n/100)-1. Report observation_count, missing_count, method and units. Example [1,2,3,4,100] ms gives P50=3 and P95=100 at n=5. Missing all observations gives `unmeasured`; partial observations give `partial`; a measured 0ms must be an explicit observation. Reusing the same clock span for several utterances is invalid source preparation.

Cost includes only supplied per-utterance charges with status=verified, amount, currency and evidence_ref. Non-synthetic verified costs also require evidence_sha256 matching a private local file under --evidence-root. This proves integrity of **operator-supplied evidence**, not independent billing, tariff accuracy, invoice coverage or correctness of human attribution. Decimal arithmetic preserves supplied decimal amounts. Missing/unverified rows contribute no amount and are counted. A verified zero charge needs evidence too. A total is emitted only when every utterance has verified evidence and exactly one currency is present. Otherwise total=null and only verified_subtotals by currency are shown; no exchange conversion or free-use assumption occurs. Do not assign an entire multi-case invoice independently to each case; apportion it in the evidence first.

Original `EVAL_RESULTS.csv` columns remain unchanged. Generated cells are human-readable rates including counts, or UNMEASURED/PARTIAL; JSON is the machine-readable source. `asr_error` maps to asr_transcription_error; numeric ASR detail is in JSON. `sample_count` means utterances. Original mode column holds explicit synthetic/text_simulation/replay/real_audio/unmeasured labels. No independent acceptance follows from `split=held_out` or a supplied D04 audit.
